Go Nilgris: Technical Documentation

A comprehensive guide to the Go Nilgris tour booking website. This document details the architecture, data flow, styling, and core functionalities.

1. Core Technologies

The application is built on a modern, robust tech stack designed for performance, security, and scalability.

  • Next.js 15: The React framework for production. It enables features like Server Components, Server Actions, and Static Site Generation (SSG).
  • React 18: The core library for building user interfaces.
  • Firebase: Used as the backend-as-a-service.
    • Firestore: A NoSQL document database for all application data (tours, bookings, etc.).
  • Tailwind CSS: A utility-first CSS framework for rapid and consistent styling.
  • ShadCN/UI: A collection of beautifully designed and accessible UI components built on top of Radix UI and Tailwind CSS.
  • Razorpay: The payment gateway for processing online tour bookings securely.
  • Lucide React: A library of simply beautiful and consistent icons.
  • React Hook Form & Zod: For robust, type-safe form validation and management.

4. Database Deep Dive (Firebase Firestore)

All application data is stored in Firebase Firestore. The file src/lib/firebase.ts contains all functions for interacting with the database. These are designed as Server Actions for maximum security and performance.

4.1. Firestore Collections

Collection: `tour_packages`

Stores the main details for each tour package. The document ID is the URL-friendly slug.

  • Schema: See TourPackage in src/types/index.ts.
  • Fields: name, slug, duration, overview, inclusions, exclusions, notes, disclaimers, itinerary, faqs.

// Fetch all tour packages
// Used on: Homepage, Admin Dashboard
export const getTourPackages = async (): Promise => {
    const tourPackagesCol = collection(db, 'tour_packages');
    const snapshot = await getDocs(tourPackagesCol);
    return snapshot.docs.map(doc => ({...doc.data(), id: doc.id } as TourPackage));
}

// Create or update a tour package
// Used in: Admin > Edit Tour Page
export const createOrUpdateTourPackage = async (tourData: Omit) => {
    const docRef = doc(db, 'tour_packages', tourData.slug);
    const priceDocRef = doc(db, 'packages', tourData.slug);
    
    const { price, ...tourPackageData } = tourData;

    const batch = writeBatch(db);
    
    batch.set(docRef, tourPackageData, { merge: true });
    batch.set(priceDocRef, { slug: tourData.slug, price: price }, { merge: true });
    
    await batch.commit();
}

Collection: `bookings`

Stores every booking made by customers.

  • Schema: See Booking in src/types/index.ts.
  • Fields: bookingId, packageSlug, bookingDate, memberCount, totalAmount, passengers, selectedSeats, razorpayPaymentId.

// Save a new booking after successful payment
// Used in: Booking Page (Payment Handler)
export const saveBooking = async (bookingData: Omit) => {
  try {
    const docRef = await addDoc(collection(db, 'bookings'), bookingData);
    return docRef.id;
  } catch (e) {
    throw new Error('Could not save booking');
  }
};

// Get all bookings
// Used in: Admin > Bookings Management
export const getBookings = async (): Promise => {
    const querySnapshot = await getDocs(collection(db, "bookings"));
    const bookings = querySnapshot.docs.map(doc => ({ id: doc.id, ...doc.data() } as Booking));
    // Sort by most recent date
    bookings.sort((a, b) => new Date(b.bookingDate).getTime() - new Date(a.bookingDate).getTime());
    return bookings;
}

Collection: `availability`

Stores seats that are manually blocked by an admin for a specific tour on a specific date. The document ID is a composite key: {packageSlug}_{yyyy-MM-dd}.

  • Schema: { blockedSeats: number[] }

// Get manually blocked and booked seats for a date
// Used in: Booking Page, Admin Availability Page
export const getAvailabilityForDate = async (packageSlug: string, date: string): Promise<{ blocked: number[], occupied: number[] }> => {
    if (!packageSlug || !date) return { blocked: [], occupied: [] };
    const [blockedSeats, occupiedSeats] = await Promise.all([
        getBlockedSeatsForDate(packageSlug, date),
        getOccupiedSeatsForDate(packageSlug, date)
    ]);
    return { blocked: blockedSeats, occupied: occupiedSeats };
}

Other Collections:

  • `gallery`: Stores image URLs for tour galleries, linked by `packageSlug`.
  • `packages`: Stores the price for each tour, separate from the main tour data to allow for quick price lookups.
  • `site_config`: Stores site-wide settings, like contact information.

5. User Functionality: The Booking Flow

The customer journey is designed to be a simple, 3-step process.

  1. Step 1: Booking Details. The user selects a tour date and the number of passengers. The page fetches availability for that date in parallel to enable/disable the date picker if a day is fully booked.
  2. Step 2: Passenger Info & Seat Selection. The user fills in details for each passenger and selects seats from the interactive `SeatChart` component. The total price is calculated in real-time.
  3. Step 3: Payment. The user confirms the details and clicks "Pay Now".
    • An order is created with Razorpay via the `createPaymentOrder` Server Action.
    • The Razorpay checkout modal opens.
    • On successful payment, the handler function (`processPayment`) is called.
    • The `saveSuccessfulBooking` Server Action is invoked to save the final booking to Firestore.
    • The user is redirected to the `booking/confirmation` page.

6. Admin Panel Operations

The admin panel is a local-only dashboard for managing the website, protected from public access in production environments.

Admin Protection (`src/app/(admin)/layout.tsx`)

A simple but effective check in the admin layout prevents any of its child routes from rendering in a production environment, ensuring the entire section is inaccessible on the live site.


export default function AdminLayout({ children }: { children: React.ReactNode }) {
    // If we're in a production environment, don't render the admin panel.
    if (process.env.NODE_ENV === 'production') {
        notFound();
    }

    return ( /* ... layout JSX ... */ );
}

6.1. Admin Sections

The admin dashboard is composed of several server components that fetch data and pass it to client components for interaction.

  • Tour Management: Create, view, update, and delete tour packages. Forms use `react-hook-form` for stability.
  • Bookings Management: View, search, and delete all customer bookings.
  • Gallery Management: Add and remove images for tour-specific galleries.
  • Contact Management: Update the WhatsApp and Call numbers displayed on the contact page.
  • Pricing Management: Quickly update the price for any tour package.
  • Availability Management: Manually block or unblock seats for any tour on any date.
